# Open Season — Private Group App (standalone)

The Da Boyz year-long hunt, as a portable web app: invite-only league chat + kill feed, hunt board, kill claims with confirm/dispute and proof photos, Kill Cancel cards, safe zones, Hunt Mode, opt-in location sharing, danger proximity alerts, and a Marine career rank system (XP / Recruit → Sergeant Major). Black-and-orange, mobile-first, installable to the home screen. Zero npm dependencies — one Node.js server.

This is the standalone deployable build (the Muse prototype/private app stays where it is; this folder is a fresh portable implementation of the same locked rules).

## Run it locally

```bash
node server.js            # http://localhost:3000
PORT=3100 DATA_DIR=/tmp/os-data node server.js
```

## Deploy to Render (exact steps)

1. **Push this folder to a Git repo** (GitHub is easiest): make this folder the repo root, `git init && git add . && git commit -m "Open Season app"`, create an empty GitHub repo, push. (Alternatively use Render's Docker deploy with the included `Dockerfile`.)
2. In Render (Christian's account): **New + → Web Service → connect the repo**. Render reads `render.yaml` if you choose "New + → Blueprint" — that is the fastest path and pre-fills everything below.
3. If configuring by hand: Runtime **Node**, Build command `npm install --omit=dev` (no dependencies, so it's instant), Start command `npm start`, Plan **Free** to start.
4. **Environment variables** (Render → service → Environment):
   - `LEAGUE_CODE` = `BOYZ-2027`
   - `DATA_DIR` = `/var/data`
   - `ADMIN_RESET_CODE` = a secret only Christian knows (founder emergency: clears all other claims/PINs via the admin panel API). Don't commit it anywhere.
   - `SEASON_START_ISO` (optional) — defaults to Jan 1, 2027, midnight EST.
5. **⚠ Persistent storage — read this before going live.** Render free web services have an **ephemeral filesystem**: league data (claims, chat, kills, XP) is **wiped on every restart, redeploy, and spin-down**. Pick one:
   - **Attach a Render persistent disk** (paid, ~$0.25/GB/mo — 1 GB is plenty): service → Disks → mount path `/var/data`. The lines are pre-written, commented, at the bottom of `render.yaml`.
   - **Or** swap the store: all persistence lives in `lib/store.js` (`load()`/`save()`) — re-implementing those two functions against a hosted Postgres (e.g. Render Postgres / Neon free tier) makes the app disk-independent. Nothing else in the codebase touches the filesystem.
6. Deploy, open the Render URL on a phone, and walk the roster through claiming (below).

### Free-tier caveats (known, accepted)
- **Sleep on idle:** free web services spin down after ~15 min without traffic; the next open takes ~30–60 s to wake. Fine for a 16-man league; a $7/mo Starter instance removes it.
- **Ephemeral disk:** see step 5 — the real risk. Until the disk/DB choice is made, treat the free deploy as a test run.
- Location sharing works **while the app is open** (web-app limit), same as designed. Always-on background tracking needs a native app.

## How the league uses it
1. Open the link → **Add to Home Screen** (iPhone: Safari → Share → Add to Home Screen; Android: Chrome ⋮ → Add to Home screen).
2. Pick your name, enter the league code `BOYZ-2027`, set a PIN (4+ characters) — that claims your spot. Later visits: same name + PIN to log in.
3. Set safe zones (home/work/church, ~150 m) — inside one, your map pin hides automatically and the league is told you're at a safe zone (the label only — never the location).
4. Turn location sharing on to hunt. **Turning it off mid-season = out** (league rule, enforced by the server). Driving is different: sustained speed over ~20 mph (while the app is open) hides you automatically as 🚗 Driving until you stop — that never puts you out. Heading out on purpose? Flip on **🎯 Hunt Mode** (My Card) instead — it turns sharing on, keeps your screen awake and GPS hot while the app is open, and lets the league know (anonymously) that someone's hunting.
5. Founder (Christian) / Vice (Twigg) get admin controls in the Rules tab: season setup (platform, class, pot, marked man), combo event wins (+300 XP), manual XP adjusts with a note, disputed-kill settlement, and season close.

## Nov 7, 2026 — Round 4: safe-zone announcements + driving mode

- **Safe-zone announcements:** safe zones already hid your pin; now entering one also **tells the league**. The feed gets a "🛡 *Name* is at a safe zone — WORK" entry and every surface (Board, Map list, profile) shows "🛡 At a safe zone — WORK" — the zone's label (HOME / WORK / CHURCH) and nothing else. Your coordinates still never leave the server: other hunters' payloads carry the label and a null position, verified by test. Announcements fire **once per continuous stay**; leaving and re-entering within **15 minutes** does not re-announce (GPS boundary jitter), and leaving clears the status silently. If two of your zones overlap, the first matching one labels you. The status is informational for kill claims — it does not hard-block them; real-world disputes stay the Founder's call, as before.
- **Automatic driving mode:** while the app is open, the client forwards each fix's device-reported speed (`coords.speed`); when a phone reports none, the server derives speed from consecutive fixes (distance ÷ time). **Enter:** speed above **9 m/s (≈20 mph)** on **2 consecutive fixes**. **Exit:** below **2 m/s** on 2 consecutive fixes (a mid-range fix resets the streak — the speed must be sustained either way). While driving: your pin is hidden, the feed posts **one** "🚗 *Name* is driving" entry per trip, Board/Map/profile show 🚗 Driving, **kill claims against you are rejected server-side** ("target is driving" — no hits on a driver), and danger proximity alerts are suppressed both to and from you. When you stop, sharing resumes on its own — unless you're inside a safe zone, whose label takes display precedence.
- **Driving is a third state, not the sharing toggle.** It never marks anyone out — not in a live season, not in scrimmage; only the manual sharing toggle does that. Honest limit, same as all location in this app: detection only works **while the app is open** on the hunter's phone.

## Nov 7, 2026 — Round 6: Hunt Mode

Location in a web app only updates while the app is open on screen — Hunt Mode is the in-app answer, built for how the hunt actually gets played:

- **🎯 The toggle (My Card):** flip it on when you head out. It **turns location sharing on with it** (and turning Hunt Mode off never touches sharing), stamps the hunt start, and persists server-side. Watching members and dead/out hunters can't hunt.
- **While hunting (client):** the app requests a **Screen Wake Lock** (feature-detected, graceful where unsupported; re-acquired whenever you return to the app mid-hunt) so the screen — and therefore the GPS — stays live, and posts fixes on a hot cadence: at most every ~3 s, on ≥10 m of movement, with a ~5 s heartbeat for a parked hunter. A pulsing **🔴 YOU'RE LIVE — HUNT MODE** banner with elapsed hunt time sits at the top of every tab. First enable shows the honest fine print once: *it keeps the screen on and GPS hot, so it eats battery.*
- **The blast:** the off→on transition — and only the transition — sends **one anonymous push** to every *other* claimed hunter: "⚠️ Someone's hunting. Open the app — your pin goes live." The payload is fixed text with **no name or identifier of any kind** (test-verified by decryption), plus one anonymous feed entry, "🎯 Someone started hunting." At most **one blast per hunter per 30 minutes** — toggle spam stays quiet — and only while the hunt is open: **live season or scrimmage**. In plain setup the toggle, wake lock, and banner all work; nothing blasts.
- **Freshness:** the 🎯 HUNTING marker (Board, Map list, map pins, profiles) is computed **server-side** from pin freshness — the persisted flag plus a fix within **10 minutes**. Close the app mid-hunt and the marker quietly goes stale with your pin: no elimination, no feed spam, and your own toggle still shows your hunt as on.
- **Safety interplay:** Hunt Mode never overrides anything. Safe zones still hide the pin (label public as always), driving mode still hides the pin and rejects claims against the driver, dying ends your hunt, and Hunt Mode itself never puts anyone out — only the manual sharing toggle does that.

## Nov 7, 2026 — Round 7: league ping + Location Check

Two ways to make the league show up — one social, one enforcement:

- **📍 Ping the league (any hunter):** a **Ping the league** button on My Card. Any claimed, alive, non-watching hunter can send it: every *other* claimed, alive, non-watching hunter gets a push — "📍 {Name} pinged the league — open the app to update your location." — plus a named feed entry. The sender is named on purpose (it's a roll call, not a stealth mechanic). One ping per hunter per **hour** (`PING_COOLDOWN_MS`); a ping inside the window gets a 429 with the remaining wait, and the button counts the cooldown down. Works in every phase.
- **📍 Location Check (Founder/Vice):** the enforcement call, from the admin panel. **Settings** — reminder interval (5–120 min, default 15) and deadline (15–480 min, default 60) — are edited in the admin panel and **snapshot at call start**: changing them mid-call never alters a running call. One call at a time; starting in plain setup is refused.
- **Targets** snapshot at the start: in a **live season**, claimed alive non-watching hunters with **sharing ON**; in **scrimmage**, every claimed alive non-watching hunter (sharing irrelevant — and scrimmage takes precedence if both apply). Targets get the start push ("You have {deadline} minutes") and a feed entry naming the admin who called it.
- **Checking in is automatic:** any position fix the server receives at or after the call start checks that hunter in — including fixes whose pin is hidden by a safe zone or driving mode (the server sees the fix; the league just doesn't see the pin). While a call runs, every hunter sees a countdown banner with his own status ("✅ You're checked in" / "⏳ NOT checked in yet") and the check-in board on the Board tab (names + ✅/⏳ — the payload block carries **no location data**, ever).
- **Reminders + deadline:** a scheduler tick (~30 s, `CHECK_TICK_MS`) works purely off stored timestamps. Every interval it pushes each not-yet-checked-in target ("📍 Still waiting — {N} min left to check in or you're OUT."); checked-in hunters are never reminded. At the deadline, **live** stragglers are eliminated through the normal elimination machinery with the reason recorded as a check-in timeout — **no XP changes hands** (it is not a kill: no death charge, no ledger entries) — with a ☠️ push to the eliminated man and a public feed entry per elimination, processed exactly once per target. In **scrimmage** nobody is eliminated: one wrap-up entry names who *would* have been out. An admin can **call a check off** at any time — no elimination is ever applied from a canceled call — and ending a scrimmage or closing the season mid-call closes it quietly. A target eliminated by other means mid-call (a confirmed kill, sharing off) is skipped at the deadline, never double-processed.
- **⚠️ Free-tier sleep caveat:** the scheduler runs inside the app process, and Render's free tier puts that process to sleep when idle. Reminders and the deadline can only fire while the server is awake — if it was asleep when they came due, they process on the next tick after it wakes (any hunter opening the app wakes it). The catch-up is deliberate: at most **one** reminder per straggler no matter how many intervals were slept through, then the deadline applies if it passed. On a paid (always-on) instance the timings are exact.

## Nov 7, 2026 — Round 8: push hotfix + diagnostics

**The live bug:** on iOS the Founder had 2 stored subscriptions and the test push reported "0 of 2 accepted" — Apple's push service (web.push.apple.com) was rejecting every send, and the old response carried only counts, so there was no way to see *why*. The crypto had only ever been verified against our own fake push service, which shares assumptions with the code it tests. This round makes the next live test decisive and clears the known suspects:

- **Statuses are surfaced end-to-end (diagnostics):** every send now records the push service's raw HTTP status per attempt (0 = the send never got an answer — network/encryption failure, with the reason kept). `POST /api/push/test` returns them, and the **Send test push** toast names them on any rejection: *"Test push sent — 0 of 2 accepted (push service said: 403, 403)."* Full acceptance keeps the old wording. **How to read the codes:** **201/2xx** = accepted, delivered · **400** = the payload itself is malformed · **403** = a VAPID/subscription problem (our token isn't valid for that subscription — e.g. it was minted against rotated keys) · **404/410** = the subscription is dead and gets pruned.
- **403 prunes now, like 404/410:** a subscription the push service answers 403 can never succeed — it's rejected for *our* credentials, not for a transient reason — so it's cut on the spot instead of poisoning every future send count. Status-0 failures (no answer at all) are NOT pruned: a dead network is not a dead subscription.
- **VAPID subject:** the default `sub` claim is now the app's real https origin (`https://open-season.onrender.com`) instead of a `mailto:` at a fake local domain — Apple is documented to be picky about the subject, and an https origin is a valid RFC 8292 subject. `VAPID_SUBJECT` env still overrides.
- **Alerts toggle forces a fresh subscription:** turning Alerts **on** now unsubscribes any existing browser subscription first (client- and server-side) and only then subscribes with the server's *current* public key — so a stored subscription can never again silently point at yesterday's rotated keys. Toggling alerts off and back on is the manual version of the same cure.
- **Independent-vector verification (tests):** push bodies are now also decrypted by a second, separately written routine (HKDF expanded by hand, the 0x02 record delimiter asserted explicitly), and the VAPID JWT is asserted end-to-end for an Apple-shaped endpoint — `aud` exactly `https://web.push.apple.com`, `exp` within 24 h, `sub` the new default, ES256 signature verified — so the suite no longer grades the crypto purely with its own mirror.

## Backup & Restore (Founder/Vice — insurance against storage wipes)

Render's free tier can wipe this app's storage without warning, and a wipe means the whole league — claims, PINs, XP, ledger, chat, kills — is gone. The Admin panel (Rules tab → **League backup**) is the insurance:

- **⬇ Download backup** — saves one JSON file (`open-season-backup-YYYYMMDD-HHmm.json`) with the *complete* league state: roster with PIN hashes, sessions, XP ledger, kills, chat/feed, bounties + bounty history, season archives, league settings, and the push (VAPID) keypair, so push subscriptions keep working after a restore. **When:** before anything risky (redeploys, settings experiments) and after big season moments (a Reckoning, a season close, a trophy day). Keep the file somewhere that isn't the app — Files/iCloud, or email it to yourself.
- **⬆ Restore from backup** — pick a backup file, read the confirm dialog (it shows the backup's date, season, and size), and confirm. The current league is **replaced entirely** — validated first, written atomically, so a bad file changes nothing. Every client sees the restored league on its next refresh (the restoring admin stays signed in; everyone else's session reverts to whatever the backup holds, and PINs always work).
- **Habit worth having:** download a backup of the *current* league before restoring an older one — a restore has no undo of its own.
- **The app nags so you don't have to remember:** downloads stamp `league.lastBackupAt`, and during a live season (or scrimmage) the Founder/Vice get a stale-backup banner once it's missing or over 7 days old — see Round 5 above. Restoring an old backup also restores its old stamp, so the banner correctly comes back until a *fresh* backup is downloaded.

Restore uploads are capped at 200 MB (`RESTORE_MAX_BYTES`); proof photos dominate the size, and a real league sits far below that.

## Rules enforced by the server
- Season 1 is in **setup until Jan 1, 2027** — kill claims are locked until go-live (countdown in the app).
- Kill claim → victim **confirms** or **disputes** → Founder/Vice settles disputes (an admin who is a party to the kill can't settle it). Stealth killers stay hidden until confirmation.
- On a confirmed kill: killer **+100** (stealth **+125**), **+50** bonus if the victim was the marked man; victim **−75** and out.
- **Kill Cancel:** one card per player per season; the victim has **24 hours** from confirmation to play it — the kill is **voided** (all of its XP effects clawed back via offsetting ledger entries, collected bounties restored to the board), nobody dies, and the victim is **immune to new kill claims for 24 hours**. The killer may **override** within 24 hours by burning his own card: the kill re-stands (effects re-credited, death re-charged, bounties re-collected) and both cards are spent. A canceled kill counts for nothing in any tally. (No Kill Cancel at the Reckoning — the Reckoning itself is settled off-app and recorded via Close Season.)
- **Career XP / Marine ranks** (never reset by seasons): Recruit 0 · Boot 100 · Private 250 · PFC 450 · Lance Corporal 700 · Corporal 1,000 · Sergeant 1,400 · Staff Sergeant 1,900 · Gunnery Sergeant 2,500 · Master Sergeant 3,200 · First Sergeant 4,000 · Master Gunnery Sergeant 5,000 · Sergeant Major 6,500. Deaths can demote, but XP never goes below 0 and a **fresh promotion is protected** from demotion on the very next death. Combo event win **+300**, Last Man **+500**, Deadliest Man **+250** — paid at season close; career XP survives the reset. Every XP change is in the ledger (Founder/Vice can view it via the API state).
- **Safe zones announce, label only:** entering a safe zone posts a feed entry and a public "🛡 At a safe zone — LABEL" status; the hunter's coordinates never appear in any other hunter's payload. One announcement per stay, 15-minute re-entry cooldown, silent exit. The status alone never blocks a kill claim (the Founder settles real-world disputes).
- **Driving mode (automatic, app open only):** sustained speed > 9 m/s (≈20 mph) across 2 consecutive fixes — device-reported `coords.speed`, or a position-derived estimate when the device reports none — hides the pin, posts one "🚗 driving" feed entry per trip, shows 🚗 Driving on Board/Map/profile, rejects kill claims against the driver, and suppresses danger alerts to/from him. Speed < 2 m/s across 2 consecutive fixes restores normal sharing (safe-zone status takes display precedence when both apply). Driving **never** eliminates anyone; only manually turning sharing off mid-season does.
- **Hunt Mode (Round 6):** the My Card toggle persists `hunting` + `huntStartedAt` server-side; turning it on turns sharing on with it (off never touches sharing); watching members and dead/out hunters are refused. The off→on transition fires the anonymous blast — fixed-text push (title "🏹 Open Season", body "⚠️ Someone's hunting. Open the app — your pin goes live.", tag `hunt-start`) to every other *claimed* hunter plus one anonymous feed entry — at most once per hunter per 30 minutes (`HUNT_BLAST_COOLDOWN_MS`), and only while the hunt is open (live season or scrimmage). The public `hunting` marker is computed server-side as persisted-flag AND a position fix within 10 minutes, so a closed app goes stale quietly; the hunter's own record additionally carries `huntingOn` / `huntStartedAt` / `huntHintSeen`. Hunt Mode never overrides safe zones or driving mode, and never eliminates anyone.
- **League ping (Round 7):** `POST /api/ping` — any claimed, alive, non-watching hunter pushes every *other* claimed, alive, non-watching hunter (tag `league-ping`, body names the sender) plus one named feed entry, at most once per hunter per hour (`PING_COOLDOWN_MS`); inside the window the route answers 429 with `retryAfterMs`. Dead/watching senders get a 400. Allowed in every phase.
- **Location Check (Round 7):** Founder/Vice only. Settings (`league.checkSettings`, reminder interval 5–120 min / deadline 15–480 min) snapshot into the call at start — mid-call edits never alter a running call. One call at a time; refused in plain setup. Targets snapshot too (live: alive + sharing ON; scrimmage: everybody in — scrimmage precedence, practice only). A target checks in when the server receives any fix from him at/after the start — safe-zone-hidden and driving fixes count. A ~30 s scheduler tick (`CHECK_TICK_MS`), driven purely by stored timestamps, sends interval reminders to stragglers only (at most one catch-up reminder per straggler after a server sleep) and at the deadline eliminates live stragglers with the standard out state and reason `check-in timeout` — **no XP or ledger change of any kind** — pushing the eliminated man and posting one feed entry per elimination, exactly once per target; a scrimmage deadline eliminates nobody and posts one "would have been out" entry. Cancel voids a call outright; scrimmage-end and season-close close a running call quietly; targets eliminated by other means mid-call are skipped at the deadline. The public payload block shows starter, deadline, snapshot settings, and per-target name + checked-in status — never any location data. On the free tier the tick only runs while the server is awake (see the Round 7 section).
- Watching members (Bryce) can claim, chat, and hold rank, but can't hunt or be hunted.

## Layout
- `server.js` — HTTP server + all API routes and game rules (zero dependencies)
- `lib/xp.js` — rank ladder (with insignia specs + descriptions), XP table, demotion/protection logic, ledger writes
- `lib/store.js` — the one swappable persistence module (JSON file under `DATA_DIR`, seeded roster on first boot; tolerates older data files)
- `lib/achievements.js` — career stats + achievement definitions, derived from the ledger/board/archive
- `lib/push.js` — Web Push protocol from Node crypto only (VAPID ES256 JWT + aes128gcm payload encryption)
- `public/` — the PWA (map uses Leaflet + OpenStreetMap tiles with a dark CSS filter and a built-in no-tiles fallback grid; `public/sw.js` is the push-only service worker)
- `tests/run-tests.js` — integration suites (see Tests above)
- `Dockerfile`, `render.yaml` — deploy configs
